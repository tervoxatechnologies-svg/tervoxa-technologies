TERVOXA TECHNOLOGIES
COMPLETE SETUP, ROADMAP, TESTING, AND DEPLOYMENT GUIDE

======================================================================
1. PROJECT OVERVIEW
======================================================================

Tervoxa Technologies is a full-stack web application consisting of:

- Public marketing website
- About, services, process, FAQ, legal, and contact pages
- General enquiry form inside the FAQ page
- Project enquiry form inside the Contact page
- MongoDB inquiry storage
- Google Forms synchronization
- User registration and login
- Optional Google OAuth login
- Client Dashboard
- Admin Dashboard
- Project registration and status tracking
- Admin project notes and status updates
- Responsive navigation and layouts
- Animated cards, buttons, sections, and dashboard panels

The project has two applications:

Frontend:
  client\

Backend:
  server\

The root project scripts control both applications.

For MongoDB Atlas:

1. Create a cluster.
2. Create a database user.
3. Configure the database password.

6. Never commit the connection string to source control.

Do not expose the backend .env file publicly.


======================================================================
7. ADMIN ACCOUNT SETUP
======================================================================

The administrator bootstrap logic is located at:

  server\src\config\admin.js

Configure these environment values:

  ADMIN_EMAIL=admin@yourdomain.com
  ADMIN_PASSWORD=Use-a-long-random-password

Use:

- A real administrator email address
- A strong unique password
- A password that is not used anywhere else

When the server starts, it creates or updates the admin account.

If the values are empty, the server reports that admin bootstrap was
skipped. The application can still run, but automatic admin login setup
will not be available.


======================================================================
8. GOOGLE FORMS SETUP
======================================================================

Google Forms synchronization is implemented in:

  server\src\services\google-forms.service.js

Configuration is loaded in:

  server\src\config\env.js

Required values:

  GOOGLE_FORM_VIEW_URL=https://docs.google.com/forms/d/e/FORM_ID/viewform
  GOOGLE_FORM_ACTION_URL=https://docs.google.com/forms/d/e/FORM_ID/formResponse

The view URL is used by the direct Google Form button.

The action URL is used by the backend to submit form responses.

Current entry mapping:

  GOOGLE_ENTRY_FULL_NAME=entry.xxxxx
  GOOGLE_ENTRY_EMAIL=entry.xxxxx
  GOOGLE_ENTRY_PHONE=entry.xxxxx
  GOOGLE_ENTRY_COMPANY=entry.xxxxx
  GOOGLE_ENTRY_SERVICE=entry.xxxxx
  GOOGLE_ENTRY_PROJECT=entry.xxxxx

Each entry ID must match the correct Google Form question.

To inspect entry IDs:

1. Open the Google Form preview.
2. Open browser developer tools.
3. Inspect the form fields.
4. Find names such as entry.123456789.
5. Match each entry ID to its question.
6. Add the values to server\.env.

Project enquiries send:

- Full name
- Email
- Phone number
- Company
- Service
- Project requirement
- Brief notes

Project requirement and brief notes are combined into the project field.

General enquiries send:

- Full name
- Email
- WhatsApp number through the existing phone field
- Company
- Message

The preferred contact option is currently stored in MongoDB. It is not
mapped to a separate Google Form field unless a dedicated entry mapping
is added.

If required, add a Google Form field and configure:

  GOOGLE_ENTRY_CONTACT_PREFERENCE=entry.xxxxx

Then update the backend mapping to submit:

- No call requested
- WhatsApp only
- Morning
- Afternoon
- Evening

12. GENERAL ENQUIRY FLOW
======================================================================

The general enquiry form is located inside:

  /faq

Fields:

- Full Name
- Email Address
- WhatsApp Number
- Company / Organization
- Message
- Preferred contact option

Preferred contact options:

- No call requested
- WhatsApp only
- Morning
- Afternoon
- Evening

Backend endpoint:

  POST /api/inquiries/general

The backend:

1. Sanitizes input.
2. Validates required values.
3. Validates email and WhatsApp number.
4. Stores the inquiry in MongoDB.
5. Attempts Google Forms synchronization.
6. Returns success or an explicit error.


======================================================================
13. PROJECT ENQUIRY FLOW
======================================================================

The project enquiry form is located inside:

  /contact

Fields:

- Full Name
- Email Address
- Phone Number
- Company / Organization
- Service Required
- Project / Requirement
- Brief Notes

Backend endpoint:

  POST /api/inquiries/project

The backend:

1. Sanitizes input.
2. Requires all project fields.
3. Validates email and phone.
4. Validates the selected service.
5. Stores the inquiry in MongoDB.
6. Attempts Google Forms synchronization.
7. Returns success or an explicit error.

The Contact page also contains an Open Google Form button.

14. CLIENT DASHBOARD
======================================================================

The Client Dashboard is:

  /dashboard

A client must:

1. Register an account.
2. Log in.
3. Open the Dashboard.
4. Register a project.
5. View project status and updates.

The client Dashboard contains:

- Total projects
- Active projects
- Completed projects
- New project form
- Project list
- Project statuses

Clients can only see projects owned by their own account.

Clients cannot:

- View other clients' projects.
- Change project status.
- Add admin notes.
- Access admin-only update endpoints.

  PATCH
  OPTIONS

easier.
